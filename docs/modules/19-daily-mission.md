# 日常任务与活跃奖励

## 当前完成度

普通日常任务的状态、04:00 日界、单项领奖、活跃宝箱和一键领取均已闭环。
已有玩法会在成功业务事务中推进任务；协同出击、好友赠送电力和商店购买因对应
玩法尚未实现，任务定义和领奖规则已存在，但暂时没有进度来源。

## 客户端配置与协议

客户端从 `Mission/DailyMission.txt` 读取任务列表，从
`Mission/MissionAward.txt` 读取五档活跃奖励。打开任务页面不会向服务端拉取
列表，登录和玩法变化依赖 `TASK_VALUE_RSP`。

领奖 RPC：

- `MissionGetAward {nId, nType=0}`：领取单项任务；
- `MissionActiveAward {nId, nType=0}`：领取单个活跃宝箱；
- `MissionGetAward {nId=0, nType=1}`：一键领取所有已完成任务，以及这些任务
  产生活跃度后可领取的全部宝箱。

成功后返回 `MissionMgrMsg`：

- `nMission=1` 表示任务奖励，一键领取时携带 `tbIdList`；
- `nMission=2` 表示活跃宝箱，一键领取时携带汇总后的 `tbItems`。

## 状态编码

客户端任务键为 `(5 << 16) | taskId`。

- `101～110`：第 0 位是已领奖标记，第 1～31 位是进度，即
  `taskValue = progress * 2 + claimed`；
- `30000`：当前活跃度原始数值，上限 100；
- `30001`：第 1～5 位分别标记五档活跃宝箱是否领取。

这些字段由服务端保护，通用 `TASK_CHANGE_REQ` 无法覆盖。

## 活跃宝箱

门槛依次为 10、25、50、75、100，奖励完全来自客户端 `MissionAward.txt`。
当前没有战令活动，因此 `15-52-1-1-N` 战令经验不会入账，也不会出现在一键领取
的 `tbItems` 中。其他奖励复用统一背包、货币和少女名册通知。

## 日界和事务

运营日采用 Asia/Shanghai 04:00。玩家登录、任务进度变化和领奖前都会校正
`dailyMissions.operationalDate`；跨日时原子清空 `101～110`、`30000` 和
`30001`。进度、领奖位、活跃度和实际奖励在同一个 `JsonStore.update()` 中提交，
重复领奖不会产生奖励。
