# 悬赏战斗

## 当前完成度

**核心可用。** 四类悬赏、六档难度已经具备入场、失败和通关结算闭环；掉落数量
依据 BWIKI 明细复原，道具坐标、地图、协议和盗宝娘池依据当前客户端资源复原。

## 协议

客户端使用 `LuaCall` 数字命令：

- `sCmd=50`：进入，参数为 `id`、`diff`、`nFormationId` 和可选 `key`；
- `sCmd=51`：通关，参数为 `nActivityId`、`nDiff`、`nFormationId`、金币本实际
  拾取量、盗宝娘状态和战斗统计；
- `sCmd=52`：失败。

进入请求是直接的 50 命令；客户端通过 `GameManager.SendInfoToServer` 发送通关
和失败时，会形成 `252 -> 51/52` 的双层包装。网关同时接受直接和 252 包装形式，
回调仍使用客户端注册的 50/51/52。

成功进入返回 `tbData.id/diff`、`tbDrop`、`tbDropItems` 和
`tbSpeThiefDrop`。成功通关返回 `tbData` 奖励数组、`nMasterExp` 和
`nCardExp`。

## 规则与状态

- 活动 ID 1 是晶币，2-6 是五属性角色经验，7 是武器经验，8-12 是五属性突破；
- 晶币和武器经验每日开放；经验与突破周一生物、周二幽能、周三机械、周四防疫、
  周五侵蚀，周末全部开放；
- 非开放日支持客户端两类钥匙，道具只在成功结算时消耗；
- 店长达到 35 级前，所有悬赏实际电力消耗减半，奇数消耗向上取整；
- 入场仅校验体力，通关事务内才扣除，因此失败或退出不耗体力；
- 同一账号、活动、难度和完成次数使用确定性随机种子。失败不增加完成次数，
  重新进入会得到相同随机额外掉落和盗宝娘；
- 每类每日两次额外奖励，上海时区 04:00 重置；
- 最高通关难度写入任务组 9 的 `100 + activityId`；
- 每日额外次数写入任务组 9 的 `4000 + eventType`；
- 通关事务同时处理体力、钥匙、奖励、主角经验、难度进度、每日次数和随机序号。

热重载或短暂断线使连接内入场状态丢失时，网关会按持久化的完成次数恢复本局，
以便客户端正在重试的 51 结算能够继续。

## 奖励与盗宝娘

固定和每日额外奖励由服务端直接保留。晶币本客户端只回传地图上实际拾取的随机
晶币，例如简单难度客户端配置为 1600、实战可能回传 1580；服务端只用该值替换
随机部分，并限制在本局随机上限内，不会覆盖固定 6400 和每日额外 10000。

盗宝娘按客户端关卡表的总计 10% 概率出现。服务器下发对应怪物和掉落 ID，通关
时仅接受本局已配置、客户端确认击破并拾取的少女礼物或绮想天尘。

## 验证

- `test/bounty-data.test.ts`：72 个关卡、奖励、04:00 日界和星期轮换；
- `test/bounty-protocol.test.ts`：直接 50 与实际设备观察到的 `252 -> 51`；
- `test/bounty-persistence.test.ts`：体力、晶币、难度进度、每日次数和完成序号的
  原子结算；
- 实机日志已验证 50 能载入地图，51 的实际金币字段为拾取的随机部分。

## 已知缺口

- 双倍悬赏活动开关尚无服务端活动日历，因此当前不会自动把固定奖励再翻倍；
- 战斗统计和击杀数组只记录，不用于强校验战斗合法性；
- 最后一次结算响应的去重仍主要在当前连接，跨进程重复包的完整幂等键尚未恢复；
- 客户端资源和 BWIKI 的少量历史数量不一致时，当前优先采用 BWIKI 数量。
