# 角色与武器抽卡

## 当前完成度

**核心可用。** 已按原客户端表复刻主要随机与保底逻辑，并完成货币、背包和计数持久化。

## 数据和卡池

- 从原始 `Gacha.txt`、星级种子、保底种子和数百个 pool 文件加载；
- 同 ID 多条配置按开始时间选择最新版本；
- 当前加载 63 个角色池、19 个武器池；
- 提供角色卡和武器 GDPL 稀有度索引，供武器强化及两类分解计算品质；
- 可计算公示星级权重和单卡概率。

服务端本身不向客户端下发“哪些卡池显示”，卡池 UI 仍由客户端配置/补丁决定。

## 抽取规则

- 单抽、十连；
- 分段星级概率；
- 十连最后一抽的 hedge 池；
- 配置次数的四星保底和 UP 保底；
- `judgeType` 对应的自选 UP、指定卡和暂存确认流程；
- FirstGet/HasCard、抽数、UP 抽数和总抽数；
- `GetItem`、UP box 和轮换版本计数；
- `GetFirstGacha` 固定池 666；
- `GetLastGacha` 查询或确认暂存结果；
- 角色、武器自选项保存到任务值。

## 成本和入账

优先消耗卡池票券；随后按卡池类型消耗免费/付费钻石或指定货币。抽卡、成本、保底
计数、奖励、少女名册和暂存清理在同一存档事务中提交。

## 验证

- `test/gacha-data.test.ts` 覆盖 63 个角色池、武器池、概率、十连 hedge、50 抽
  四星、100 抽 UP 和自选权重；
- `test/gacha-persistence.test.ts` 覆盖角色/武器成本、奖励和计数原子持久化。

## 已知缺口

- 不校验卡池开放时间、账号等级或活动有效期；
- 没有服务端卡池列表接口，客户端能显示的池取决于客户端逻辑；
- 重复角色的碎片/补偿转换没有完整复刻，只保存独立卡实例；
- 暂存抽卡的断线、过期和多次请求场景测试不足；
- 没有抽卡历史查询、邮件补发和运营审计；
- 抽卡尚未发布活动领域事件。
